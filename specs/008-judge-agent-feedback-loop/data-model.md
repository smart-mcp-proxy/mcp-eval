## Entity Definitions

### JudgeAssessment

Complete analysis for one scenario. Generated by JudgeAgent after analyzing a baseline or comparison report.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| id | string | Yes | Unique identifier, format: `judge_{uuid8}` |
| created_at | datetime | Yes | Timestamp of analysis |
| scenario_name | string | Yes | Name of analyzed scenario |
| analysis_type | enum | Yes | `baseline` or `comparison` |
| source_report_path | string | Yes | Path to input report (baseline dir or comparison JSON) |
| original_score | float | No | Similarity score (0.0-1.0) if comparison, null for baseline |
| root_cause_analysis | string | Yes | Detailed explanation of issues found (min 100 chars) |
| failure_patterns | string[] | No | Categorized patterns identified |
| improvement_suggestions | ImprovementSuggestion[] | Yes | List of suggested changes |
| judge_model | string | Yes | LLM model used for analysis |
| judge_prompt_version | string | Yes | Version of prompt template used |
| duration_seconds | float | Yes | Time taken for analysis |

**Validation Rules**:
- `original_score` required if `analysis_type == "comparison"`
- `root_cause_analysis` minimum 100 characters
- `improvement_suggestions` can be empty if trajectory is optimal

### ImprovementSuggestion

Specific proposed change to a tool definition. The "gradient" in TextGrad terminology.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| id | string | Yes | Unique identifier, format: `{assessment_id}_sug_{n}` |
| created_at | datetime | Yes | Timestamp |
| tool_name | string | Yes | Full MCP tool name, e.g., `mcp__mcpproxy__retrieve_tools` |
| aspect | enum | Yes | `description`, `parameter_description`, `example_values`, `return_schema` |
| parameter_name | string | No | If aspect targets specific parameter |
| source_location | SourceLocation | No | File location in mcpproxy-go source |
| current_value | string | Yes | Current tool description/config |
| proposed_value | string | Yes | Improved description/config |
| rationale | string | Yes | Explanation of why change improves behavior (min 50 chars) |
| chain_of_thought | string[] | No | Step-by-step reasoning |
| priority | enum | Yes | `critical`, `high`, `medium`, `low` |
| expected_score_improvement | float | No | Estimated score delta (0.0-1.0) |
| confidence | float | Yes | Confidence in suggestion (0.0-1.0) |
| evidence | EvidenceItem[] | Yes | Supporting data (min 1 item) |
| affected_scenarios | string[] | No | List of scenarios this would impact |
| status | enum | Yes | `pending`, `approved`, `rejected`, `applied`, `rolled_back` |
| applied_at | datetime | No | When suggestion was applied |
| reviewer_notes | string | No | Human reviewer comments |

**Validation Rules**:
- `rationale` minimum 50 characters
- `evidence` minimum 1 item
- `confidence` between 0.0 and 1.0
- `status` transitions: pending -> approved/rejected, approved -> applied, applied -> rolled_back

### SourceLocation

Location of tool definition in mcpproxy-go source code.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| file_path | string | Yes | Relative path from mcpproxy-go root |
| line_number | int | No | Line number where definition starts |
| accessible | bool | Yes | Whether file exists and is readable |
| search_pattern | string | No | Pattern used to locate definition |

### EvidenceItem

Supporting data from evaluation that justifies a suggestion.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| scenario_name | string | Yes | Name of scenario providing evidence |
| invocation_index | int | Yes | Which tool call (0-indexed) |
| expected_behavior | string | Yes | What was expected |
| actual_behavior | string | Yes | What actually happened |
| similarity_score | float | Yes | Score for this invocation |
| tool_call_details | object | Yes | Full tool call data (name, input, output) |

### ToolStateSnapshot

Snapshot of tool configuration for versioning and rollback.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| tool_name | string | Yes | Full MCP tool name |
| snapshot_at | datetime | Yes | When snapshot was taken |
| description | string | Yes | Tool description at snapshot time |
| parameters | object | Yes | Parameter definitions |
| return_schema | object | No | Return type schema if applicable |
| source_file | string | No | mcpproxy-go source file |
| git_hash | string | No | Git commit hash of mcpproxy-go |

### FeedbackLoopIteration

Tracks one iteration of the feedback loop for measuring improvement.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| iteration_id | string | Yes | Unique identifier, format: `iter_{timestamp}` |
| started_at | datetime | Yes | When iteration began |
| completed_at | datetime | No | When iteration finished |
| before_snapshot | ToolStateSnapshot | Yes | Tool state before changes |
| before_scores | object | Yes | Scenario scores before (name -> score) |
| applied_suggestions | string[] | Yes | List of suggestion IDs applied |
| after_snapshot | ToolStateSnapshot | No | Tool state after changes |
| after_scores | object | No | Scenario scores after (name -> score) |
| score_delta | float | No | Average improvement |
| success | bool | Yes | Whether iteration improved scores |

## Enumerations

### AnalysisType
```
baseline    # Analyzing a baseline report for trajectory optimality
comparison  # Analyzing a comparison report for divergence causes
```

### ImprovementAspect
```
description           # Main tool description
parameter_description # Description of a specific parameter
example_values        # Example values in documentation
return_schema         # Return type documentation
error_messages        # Error message clarity
```

### ImprovementPriority
```
critical  # Blocking multiple scenarios, immediate fix needed
high      # Significant score impact, should fix soon
medium    # Moderate improvement, schedule for next iteration
low       # Minor refinement, nice to have
```

### SuggestionStatus
```
pending      # Awaiting review
approved     # Approved by human/agent, ready to apply
rejected     # Rejected, won't be applied
applied      # Applied to mcpproxy source
rolled_back  # Applied then reverted
```

## Relationships to Existing Models

The Judge models integrate with existing mcp-eval models:

| New Model | Relates To | Relationship |
|-----------|------------|--------------|
| JudgeAssessment | ComparisonResult | Uses scores and per-invocation results |
| JudgeAssessment | ScenarioExecutionSummary | References scenario metadata |
| EvidenceItem | InvocationResult | Captures similar data about tool calls |
| ToolStateSnapshot | detailed_log.json | Extracts tool definitions |
